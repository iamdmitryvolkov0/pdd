# Вектор ПДД

Современный локальный тренажёр теоретического экзамена ПДД РФ для категорий A, B и M. Стек: PHP 8.3+, Laravel 12, Inertia.js, Vue 3, TypeScript, Tailwind CSS 4, Vite и SQLite.

## Возможности MVP

- основной режим из четырёх тематических блоков по пять вопросов;
- экзамен с серверным таймером и правилами дополнительных блоков;
- марафон из 800 вопросов с порционной выдачей данных интерфейсом;
- 40 билетов и практика выбранных номеров вопросов;
- неизменяемые зафиксированные ответы и идемпотентная повторная отправка;
- анонимный прогресс в серверной БД по UUID-cookie;
- статистика точности, уникальных вопросов, экзаменов и сложных вопросов;
- адаптивный интерфейс, тёмная тема по системной настройке и клавиатурное управление.

## Требования

- PHP 8.3+ с расширениями SQLite, PDO, Mbstring, OpenSSL и Fileinfo;
- Composer 2.7+;
- Node.js 22+ и npm 10+.

## Установка

### Docker

Для полной инициализации достаточно одной команды:

```bash
make init
```

Она собирает образ на PHP 8.5, запускает контейнер на [http://localhost:8088](http://localhost:8088), создаёт контейнерный `.env`, генерирует ключ приложения до запуска сервера, ждёт успешного healthcheck, применяет миграции и импортирует 800 вопросов. Репозиторий вопросов загружается во время сборки образа. На компьютере нужны только Docker с Compose и `make`: локальные PHP, Composer, Node.js и npm не используются. Конфигурация, SQLite, импортированные изображения и runtime-данные хранятся в именованных Docker volumes.

Повседневные команды:

```bash
make up       # запустить
make down     # остановить
make logs     # открыть поток логов
make shell    # войти в контейнер
make import   # повторить идемпотентный импорт
make help     # показать все цели
```

`make down` сохраняет volumes. Для намеренного полного удаления данных используйте `docker compose down --volumes` вручную.

### Без Docker

```bash
composer install
cp .env.example .env
touch database/database.sqlite
php artisan key:generate
php artisan migrate
npm install
```

SQLite настроена на foreign keys, busy timeout и WAL mode. Для разработки запустите два процесса:

```bash
php artisan serve
npm run dev
```

## Импорт вопросов

Склонируйте источник отдельно, затем укажите путь аргументом или через `PDD_DATASET_PATH`:

```bash
git clone https://github.com/etspring/pdd_russia storage/app/pdd_russia
php artisan pdd:import
```

Команда читает реальные файлы `questions/A_B/tickets/Билет N.json`, проверяет 40 × 20 вопросов, единственный правильный ответ и наличие каждого изображения. Изображения копируются в `public/images/questions` с именем по SHA-256. Повторный импорт обновляет вопросы и варианты по стабильным позициям, не удаляя записи ответов и пользовательскую историю.

Если импорт сообщает о неполном билете, отсутствующем ответе или изображении, данные не дополняются выдуманным содержимым: нужно исправить локальный источник.

## Production build

```bash
npm run build
php artisan optimize
```

Веб-сервер должен направлять запросы в `public/index.php`, а каталог `storage` — быть доступным для записи процессу PHP.

## Проверки

По правилам этого проекта автоматические тесты пока не добавляются. Доступные статические проверки и production-сборка:

```bash
find app bootstrap config database routes -name '*.php' -print0 | xargs -0 -n1 php -l
npm run build
```

Ключевые сценарии для ручной проверки после импорта: 20 правильных; одна ошибка и пять правильных дополнительных; две ошибки в разных блоках и десять правильных дополнительных; две ошибки в одном блоке; три ошибки; ошибка в дополнительном блоке; истечение времени; повторная отправка одного ответа; перезагрузка активной сессии.

## Архитектура

- `QuestionImportService` валидирует и импортирует источник;
- `QuestionSelectionService` формирует тематические наборы;
- `PracticeSessionService` создаёт сессию и фиксирует порядок вопросов;
- `AnswerSubmissionService` атомарно и идемпотентно сохраняет ответ;
- `ExamEngine` определяет состояние экзамена;
- `StatisticsService` агрегирует прогресс пользователя;
- контроллеры отвечают только за HTTP-валидацию и представление данных.

Правильные ответы экзамена не отправляются клиенту до его завершения. Сервер хранит абсолютный `expires_at`, проверяет время и принадлежность вопроса/ответа с блокировкой строки сессии.

## Правила экзамена

Реализация опирается на пункты 124 и 130–139 Административного регламента, утверждённого [приказом МВД России от 20.02.2021 № 80 (ред. от 26.05.2025)](https://www.consultant.ru/document/cons_doc_LAW_380236/): 20 вопросов, четыре неперемешиваемых тематических блока, 20 минут; один пропущенный вопрос считается ошибкой; одна ошибка даёт пять минут и пять вопросов той же группы; две ошибки в разных блоках — десять минут и два блока; три ошибки, две ошибки в одном блоке либо ошибка в дополнительном блоке означают результат «НЕ СДАЛ».

Дополнительные блоки начинаются после ответа на основную часть. Завершение пользователем неполного экзамена трактуется как отказ и результат «НЕ СДАЛ».

## Известные ограничения и развитие

- текущий набор зависит от качества и актуальности внешнего источника;
- нет регистрации и синхронизации прогресса между устройствами;
- перед публичным релизом нужны юридическая проверка контента, нагрузочное тестирование и браузерный E2E-прогон;
- следующие шаги: настройка длины тренировки, режим работы над ошибками как отдельная сессия, экспорт прогресса и installable PWA.
